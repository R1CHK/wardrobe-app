# 线上衣橱 · 微信小程序

一个可以真正跑起来的最小衣橱：拍照录入、分类管理、随时查找。
工程按「先跑通、再优化」的思路搭，代码量刻意控制在一周能读完的范围。

---

## 一、跑起来（约 15 分钟）

### 1. 用你自己的 AppID 导入

1. 打开**微信开发者工具** → 导入项目 → 选择本文件夹。
2. AppID 必须填**你自己的小程序 AppID**（在 [mp.weixin.qq.com](https://mp.weixin.qq.com) 免费注册，选「个人主体」即可）。
3. **不要用「测试号 / 游客模式」**——云开发不支持，会报 `cloud init error`。

> `project.config.json` 里的 `appid` 现在写的是 `touristappid`，导入时选择自己的 AppID 会自动覆盖。

### 2. 开通云开发

工具栏点击「云开发」→ 开通 → 新建环境（名字随意，选按量付费，有免费额度）。

`app.js` 里用的是 `wx.cloud.DYNAMIC_CURRENT_ENV`，会自动指向当前环境，**不用改代码**。
如果你有多个环境、想指定其中一个，把那行改成 `env: '你的环境ID'`。

### 3. 建集合、设权限（最关键的一步）

进入云开发控制台 → 数据库 → 新建集合，名字必须是：

```
clothes
```

然后点这个集合的「权限设置」，选：

> **仅创建者可读写**

这一步不做，会出现两种结果：要么别人能看到你的衣服，要么你自己存不进去。
选完之后，用第二个微信号登录验证一次——看不到对方的数据，才算真的配对。

### 4. 编译运行

点「编译」。首屏应该是空衣橱，点右下角「+」开始录入。

### 5. 上真机

点「预览」，用手机扫码。**这一步不能省**——模拟器里图片上传、相机、安全区都跟真机不一样。

## 三、数据长什么样

集合 `clothes`，一条记录就是一件衣服：

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | String | 自动生成 |
| `_openid` | String | 云开发自动写入，用来隔离用户，**代码里不要动它** |
| `images` | String[] | 云存储 fileID，最多 4 个，第一个是封面 |
| `category` | String | `top` / `bottom` / `dress` / `coat` / `shoes` / `bag` / `acc` |
| `seasons` | String[] | `spring` / `summer` / `autumn` / `winter` |
| `name` | String | 可为空字符串 |
| `price` | Number | 单位元，0 表示未填 |
| `createdAt` | Number | 时间戳，用来排序 |
| `updatedAt` | Number | 时间戳 |

改字段时记得同步三处：`utils/constants.js`、`pages/edit/edit.js` 的 `payload`、`pages/index/index.js` 的字段映射。

## 四、几个刻意的设计决定

**只有「一张图 + 品类」是必填。**
其它全选填。这不是偷懒，是录入完成率的关键——每多一个必填项，就多一批人不录了。

**图片先上传、再存记录，且逐张写回 fileID。**
中途失败时，已上传的不会重传。这是上传功能里最容易忽略、但体验差别最大的一点。

**编辑页和录入页是同一个页面。**
靠 `?id=` 区分。不要写两套几乎一样的表单，那是纯浪费。

**删除顺序是「先删记录，再删文件」。**
反过来的话，文件删了但记录还在，会留下一个永远加载不出图的空壳。
编辑时被移除的旧图不立即删除，等保存成功后才清理——避免保存失败把图弄丢。

**列表用 `skip/limit` 分页，不维护本地全量。**
衣橱上千件时，一次拉全量会直接卡死。

## 五、自测

改完代码想快速验证逻辑有没有坏，跑这个（不需要开发者工具）：

```bash
node tools/smoke-test.js
```

它用一个内存假数据库把「录入 → 列表 → 筛选 → 详情 → 编辑 → 删除 → 统计」整条链路跑一遍，
目前 33 项断言全过。它不能替代真机测试，但能在打开开发者工具之前抓出大部分低级错误。

## 六、常见问题

**保存时报 `permission denied`**
集合权限没设成「仅创建者可读写」。去控制台改，改完等 10 秒生效。

**图片是空白 / 一直转圈**
先确认云开发已开通。再看控制台「存储」里有没有文件；有文件但显示不出来，通常是基础库版本太低，调到 2.20 以上。

**编译报 `regeneratorRuntime is not defined`**
详情 → 本地设置 → 勾选「增强编译」。代码里用了 async/await，需要它来转译。

**提审被驳回「类目与内容不符」**
服务类目选「工具 → 效率」，不要选电商或生活服务。

**别人能看到我的数据**
权限规则没生效。用另一个微信号实测，不要只相信自己看代码的判断。

## 七、下一步可以加什么

按「投入产出」排序，前两个是性价比最高的：

1. **抠图白底**——接一个抠图 API，异步处理，把 `images[0]` 换成处理后的图。视觉提升最大。
2. **AI 属性识别**——上传后自动预填品类和颜色，能省掉一半点击。
3. **搜索框**——按名称模糊查。
4. **穿着打卡 + CPW**——从「找得到」升级到「用得上」。

暂时不建议碰：多件搭配试穿。效果调优的坑比整个项目其他部分加起来都深。
